# ssh-mcp-server 使用说明

> AI 的 SSH 网关：让 AI 客户端（ZCode / Claude 等）通过 MCP 协议在指定服务器上执行命令、传输文件，
> 而 AI 不需要（也不应该）能直连目标服务器的 22 端口。

---

## 1. 项目简介

ssh-mcp-server 是一个 **MCP（Model Context Protocol）服务器**，充当 AI 与你的服务器之间的安全网关：

- AI 侧只能调用 6 个受控工具（列服务器、执行命令、后台任务查询/终止、上传、下载），所有请求经过网关的安全策略过滤；
- 服务器侧由网关持有 SSH 密钥发起连接，目标机器的 22 端口只需对网关所在机器放行，公网完全不可达；
- 支持多台服务器统一管理，内置危险命令黑名单、敏感路径拦截、超时与输出限制。

## 2. 整体架构

```
┌──────────┐  HTTPS/HTTP + Bearer Token   ┌─────────────────────┐   走内网 SSH(22)    ┌─────────────┐
│ AI 客户端  │ ───────────────────────────→ │ Nginx 反代 → 网关服务 │ ─────────────────→ │ 内网服务器 ×N │
└──────────┘     （唯一的对外口子）          │  （部署在可达的机器上） │  （22 仅对网关放行） └─────────────┘
                                           └─────────────────────┘
```

- **本机模式**：AI 客户端与网关同机时，客户端直接以 stdio 方式拉起网关进程，无需 HTTP。
- **远程模式**：网关以 HTTP 模式跑在服务器上（仅监听 127.0.0.1），由 Nginx 反代对外暴露，AI 客户端凭 Token 访问。

## 3. 快速开始（stdio 模式）

适合网关与 AI 客户端在同一台机器的场景。

```bash
# 1. 安装依赖（要求 Node.js >= 20）
npm install

# 2. 编辑 config.json，配置你的服务器
```

`config.json` 核心字段：

```jsonc
{
  "servers": [
    {
      "id": "web1",                     // AI 调用时引用的服务器 ID
      "name": "官网生产机",               // 备注名
      "host": "10.0.0.11",              // 服务器地址（网关机器必须能连通）
      "port": 22,
      "username": "deploy",             // 建议专用低权限账号
      "privateKeyPath": "~/.ssh/id_ed25519",  // 私钥路径，支持 ~ 展开
      "hostFingerprint": "SHA256:xxxx",        // 可选：SSH 主机指纹校验（防中间人）
      "allowedFileRoots": ["/opt/apps", "/tmp"]  // 可选：限制文件操作目录（检查符号链接真实路径）
    }
  ],
  "defaults": {
    "serverId": "web1",                 // run_command 不传 server 时使用的默认目标
    "timeoutMs": 30000,                 // 命令默认超时（毫秒）
    "maxOutputBytes": 65536,            // 输出截断上限（字节）
    "maxUploadBytes": 5242880,          // 单文件上传上限（5MB）
    "maxDownloadBytes": 524288,         // 单文件下载上限（512KB）
    "maxStreamUploadBytes": 3221225472, // 流式上传上限（3GiB）
    "maxConcurrentSsh": 10              // 全局 SSH 连接并发上限
  },
  "blockedPathPatterns": [ "... 敏感路径黑名单（正则）..." ],
  "blockedCommandPatterns": [ "... 危险命令黑名单（正则）..." ]
}
```

从可信网络或服务器控制台核对并填写主机指纹：

```bash
ssh-keyscan -t ed25519 10.0.0.11 2>/dev/null | ssh-keygen -lf - -E sha256
```

```bash
# 3. 自测
node test-direct.js     # 直连执行核心逻辑
node test-mcp.js        # stdio MCP 协议全流程

# 4. 在 AI 客户端中配置（见第 5 节）
```

## 4. 服务器部署（HTTP 模式，生产推荐）

### 4.1 单文件部署（零安装，推荐）

打包产物是**自带 Node 运行时的单个可执行文件**（约 120MB），目标服务器不需要安装 Node/npm/任何依赖：

```bash
# 打包机（任意 Linux 或 WSL，需 Node >= 20 与网络）
bash scripts/build-linux.sh
# 产物：dist/ssh-mcp-server-linux
```

```bash
# 部署：只需两个文件
scp dist/ssh-mcp-server-linux config.json user@your-server:/opt/ssh-mcp/

# 服务器上直接运行
cd /opt/ssh-mcp
chmod +x ssh-mcp-server-linux
SSH_MCP_TRANSPORT=http SSH_MCP_TOKEN=<强随机token> ./ssh-mcp-server-linux
```

> 配置文件查找顺序：`SSH_MCP_CONFIG` 环境变量 → **可执行文件同目录** → 当前工作目录。
> 打包机需要网络拉取 esbuild/postject；打包产物在目标服务器完全离线可用。

### 4.2 环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `SSH_MCP_TRANSPORT` | 传输模式：`stdio` 或 `http` | `stdio` |
| `SSH_MCP_HOST` | HTTP 监听地址 | `127.0.0.1`（配合 Nginx 反代） |
| `SSH_MCP_PORT` | HTTP 监听端口 | `8080` |
| `SSH_MCP_TOKEN` | Bearer Token（静态凭据来源之一；亦可改用 config.json 的 `auth` 段，三类来源全缺时拒绝启动） | — |
| `SSH_MCP_TOKEN_FILE` | Token 文件路径（首行为 Token；与 `SSH_MCP_TOKEN` 互斥；group/other 可写时拒绝启动，建议 0600） | — |
| `SSH_MCP_TLS_CERT` / `SSH_MCP_TLS_KEY` | TLS 证书/私钥 PEM 路径（成对提供，配置后以 HTTPS 监听；亦可改用 config.json 的 `tls` 段） | 关闭 |
| `SSH_MCP_TRUST_PROXY` | 置 `1` 时信任**所有**对端的 `X-Real-IP` / `X-Forwarded-For`（**已弃用**：可被伪造绕过防爆破，建议改用 `auth.trustedProxies` 白名单） | 关闭 |
| `SSH_MCP_CONFIG` | 配置文件路径 | 可执行文件同目录的 `config.json` |

Token 生成：`openssl rand -hex 32` 或 `node scripts/gen-token.js`（等价，均为 64 位 hex 强随机值）。

### 4.3 systemd 常驻

推荐用 `EnvironmentFile` 承载凭据（配置文件 0600，token 不出现在 unit 文件中）：

```ini
# /etc/systemd/system/ssh-mcp.service
[Unit]
Description=SSH MCP Gateway
After=network.target

[Service]
WorkingDirectory=/opt/ssh-mcp
ExecStart=/opt/ssh-mcp/ssh-mcp-server-linux
Environment=SSH_MCP_TRANSPORT=http
Environment=SSH_MCP_HOST=127.0.0.1
Environment=SSH_MCP_PORT=8080
EnvironmentFile=/opt/ssh-mcp/env
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
# /opt/ssh-mcp/env（0600，root 属主）
cat > /opt/ssh-mcp/env <<'EOF'
SSH_MCP_TOKEN_FILE=/opt/ssh-mcp/token.txt
EOF
echo "换成你的强随机token" > /opt/ssh-mcp/token.txt && chmod 600 /opt/ssh-mcp/token.txt

systemctl daemon-reload && systemctl enable --now ssh-mcp
systemctl is-active ssh-mcp          # 应输出 active
curl -sk https://127.0.0.1:18080/healthz   # 启用 TLS 后加 -k；应输出 {"ok":true}
```

Token 轮换：生成新 token → 覆盖 `token.txt` → `systemctl restart ssh-mcp` → 验证旧 token 401、新 token 200。

### 4.3b 内置 TLS（可选）

```bash
# 生成自签证书（SAN 自动收录本机 IP，也可 -a IP:x.x.x.x 追加）
scripts/gen-cert.sh -o /opt/ssh-mcp/tls -n mcp-gateway
# 在 /opt/ssh-mcp/env 中追加两行：
#   SSH_MCP_TLS_CERT=/opt/ssh-mcp/tls/mcp-cert.pem
#   SSH_MCP_TLS_KEY=/opt/ssh-mcp/tls/mcp-key.pem
systemctl restart ssh-mcp
curl -sk https://127.0.0.1:18080/healthz   # 应输出 {"ok":true}
```

不配置证书时保持 HTTP。反代形态（§4.4 nginx TLS 终结）下网关自身可不开 TLS，但必须配置 `auth.trustedProxies`。

### 4.4 Nginx 反向代理 + HTTPS

```nginx
# /etc/nginx/conf.d/ssh-mcp.conf
server {
    listen 443 ssl;
    server_name mcp.example.com;

    ssl_certificate     /etc/letsencrypt/live/mcp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mcp.example.com/privkey.pem;

    # 可选：IP 白名单
    # allow 你的出口IP;
    # deny all;

    location /mcp {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;          # MCP 可能为长连接响应
        proxy_cache off;
        proxy_read_timeout 660s;
        # upload_file 的 base64 内容有约 1/3 体积膨胀，5MB 上限需要放宽 body 限制
        client_max_body_size 10m;
    }
}
```

> **云服务器安全组只需放行 443（或 80）一个端口**——六个 MCP 工具与 /upload、/download 两个流式端点全部经由这一个端口完成。
> 若连 443 都不便开放（纯内网），可用 SSH 隧道替代：
> `ssh -f -N -L 28080:127.0.0.1:18080 user@网关机`，AI 客户端连 `http://127.0.0.1:28080/mcp`。

## 5. AI 客户端接入

### 5.1 ZCode

编辑 `~/.zcode/cli/config.json`（用户级）或 `<项目>/.zcode/config.json`（项目级），也可在 **设置 → MCP** 界面添加，改完重启 ZCode 生效。

**stdio 模式（网关与 ZCode 同机）：**

```json
{
  "mcp": {
    "servers": {
      "ssh-gateway": {
        "command": "node",
        "args": ["/opt/ssh-mcp-server/server.js"]
      }
    }
  }
}
```

**HTTP 模式（网关在远程服务器，经 Nginx 或 SSH 隧道）：**

```json
{
  "mcp": {
    "servers": {
      "ssh-gateway": {
        "type": "streamableHttp",
        "url": "https://mcp.example.com/mcp",
        "headers": { "Authorization": "Bearer <你的token>" }
      }
    }
  }
}
```

### 5.2 Claude Desktop 等其他 MCP 客户端

任何支持 MCP 的客户端均可接入：stdio 客户端配置启动命令，HTTP 客户端配置 URL + Bearer 请求头，与上同理。

### 5.3 接入后怎么用

配置完成后，直接用自然语言对话即可，AI 会自动调用工具：

- "在 web1 上看下磁盘占用" → `run_command("df -h")`
- "把新版配置传到 app1 的 /opt/app/" → `upload_file(...)`
- "把 app1 上的 /var/log/app.log 拿下来看看" → `download_file(...)`

## 6. 工具参考

### 6.1 list_servers —— 列出服务器

| 项 | 说明 |
|---|---|
| 用途 | 列出 config.json 中配置的所有服务器，默认服务器带 [默认] 标记 |
| 参数 | 无 |
| 返回 | 服务器清单文本：`- <id>: <name> (<user>@<host>:<port>)` |

### 6.2 run_command —— 执行命令

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `command` | string | ✅ | 要执行的 shell 命令，须为单条、非交互命令 |
| `server` | string | ❌ | 目标服务器 ID，缺省使用 `defaults.serverId` |
| `timeout_ms` | number | ❌ | 执行超时（毫秒），默认 30000，上限 600000（background 时不适用的见下） |
| `background` | boolean | ❌ | 后台执行：立即返回 `job_id`，用 `check_job` 查询；适合编译等长任务 |
| `cwd` | string | ❌ | 执行前先切换到该目录（目录不存在报 exit_code 1） |

返回：`server`、`exit_code`、`stdout`、`stderr`；输出超过 `maxOutputBytes` 时**保留头部 60% + 尾部 40%** 并标注省略字节数（开头回显与结尾报错都能看到）；超时标注 `timedOut`。连接类网络错误（ECONNREFUSED 等）会自动重试一次。

> ⚠️ 不支持交互式程序（vim/top/tail -f）。替代写法：`cat`/`sed -i` 编辑文件、`top -bn1 | head -20` 看资源、`tail -n 200` 看日志。

### 6.2.1 check_job / kill_job —— 后台任务查询与终止

`run_command` 用 `background: true` 启动的长任务（编译、大文件处理等）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `check_job` | `job_id`（✅）、`server`（❌）、`tail_lines`（❌，默认 50，1-500） | 返回 `state`（running/done/killed）、`exit_code`（结束时）、输出尾部；顺带清理目标机上 7 天前的旧任务目录 |
| `kill_job` | `job_id`（✅）、`server`（❌） | 终止运行中的任务（TERM → 0.5s 后 KILL），state 变为 killed |

任务状态文件在目标机 `/tmp/.ssh-mcp-jobs/<job_id>/`——网关重启后仍可查询；目标机 /tmp 重启清空即自然清理。

### 6.3 upload_file —— 上传文件

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `remote_path` | string | ✅ | 服务器上的绝对路径，父目录不存在会自动创建 |
| `content_base64` | string | ✅ | 文件内容的 base64 编码 |
| `mode` | string | ❌ | 八进制权限，如 `0644`、`0755` |
| `server` | string | ❌ | 目标服务器 ID |

返回：目标路径、字节数、**服务端实测 md5**（用于完整性校验）。单文件上限 5MB（`defaults.maxUploadBytes` 可调）；GB 级大文件请用网关流式上传端点（见 6.5）。

### 6.4 download_file —— 下载文件

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `remote_path` | string | ✅ | 服务器上的绝对路径（目录会报错） |
| `max_bytes` | number | ❌ | 大小上限，默认 524288（512KB） |
| `server` | string | ❌ | 目标服务器 ID |

返回：`size`、`encoding`（文本=`utf8`，二进制=`base64`）、`content`、`md5`。超限时明确报错并建议用 run_command 分段读取。服务端对 `max_bytes` 有 5MB 硬上限；GB 级大文件请用网关流式下载端点（见 6.5 末尾）。

### 6.5 大文件上传 —— POST/PUT /upload（流式端点，默认上限 3GB）

MCP 的 `upload_file` 走 base64/JSON，只适合中小文件（GB 级文件会变成约 1.33 倍体积的
巨型 JSON 字符串，协议上不可行）。大文件走网关的流式端点：请求体直接管道到目标机 SFTP
（网关恒定内存、不落盘），完成后返回**远端实测 md5**：

```bash
TOKEN=<你的token>
# POST：curl 流式读文件，不占内存
curl -X POST -H "Authorization: Bearer $TOKEN" \
     --data-binary @bigfile.iso \
     "http://127.0.0.1:18080/upload?path=/opt/bigfile.iso"
# PUT 等价：curl -T bigfile.iso -H "Authorization: Bearer $TOKEN" "http://.../upload?path=/opt/bigfile.iso"
# 可选参数：&server=<服务器id>  &mode=0600
# 成功响应：{"ok":true,"remotePath":"/opt/bigfile.iso","bytes":3221225472,"md5":"..."}
```

### 6.5b 大文件下载 —— GET /download（流式端点，不限大小）

`download_file` 走 base64/JSON 同样只适合小文件。大文件用流式下载端点（SFTP 读流直透
HTTP 响应，网关恒定内存；响应头 `X-Md5`/`X-File-Size` 先行返回供校验）：

```bash
curl -H "Authorization: Bearer $TOKEN" \
     -o bigfile.iso \
     "http://127.0.0.1:18080/download?path=/opt/bigfile.iso"
# 可选参数：&server=<服务器id>；错误时返回 JSON（404 文件不存在 / 400 路径非法或被黑名单拦截 / 500 传输失败）
```

鉴权、防爆破、审计（`download_stream` 条目）与 /mcp、/upload 同一套；不做断点续传。

| 查询参数 | 必填 | 说明 |
|---|---|---|
| `path` | ✅ | 目标绝对路径（`/` 开头），父目录自动创建、覆盖写 |
| `server` | ❌ | 目标服务器 ID（省略用默认） |
| `mode` | ❌ | 八进制权限，如 `0600` |

- 上限 `defaults.maxStreamUploadBytes`（默认 3GiB=3221225472，config.json 可调更大）；
- 超限返回 413 且**不留半截文件**；客户端中断同样清理远端残片；
- Bearer 鉴权、防爆破封禁、审计（`upload_stream` 条目）与 /mcp 同一套；
- 经 Nginx 反代时为 `/upload` 放开 `client_max_body_size`（`0` 不限）并 `proxy_request_buffering off;`，直连/隧道部署无需任何改动；
- 上传时长不限（网关已关闭请求超时），3GB 视带宽约 1~10 分钟，远端 md5sum 另需数十秒。

## 7. 安全配置

### 7.1 鉴权与凭据

HTTP 模式**强制 Bearer 鉴权**，支持三类凭据来源（可并存，任一匹配即通过）；三类全缺时网关拒绝启动：

| 来源 | 配置方式 | 适用场景 |
|---|---|---|
| 环境变量静态 Token | `SSH_MCP_TOKEN=xxx`（身份固定为 `env`） | 单人使用，最简部署（向后兼容） |
| 多静态 Token | `config.json` 的 `auth.tokens[]` | 多人/多客户端接入，按 `id` 区分身份，支持过期与禁用；可用 `servers` 字段限定该 Token 只能访问指定服务器（分级授权） |
| HMAC 派生 Token | `config.json` 的 `auth.hmac` | 自动轮换：两端只存 master secret，派生 Token 定期变化（注意：HMAC Token 不受 `servers` 白名单限制，权限等同管理员，仅发给完全可信的调用方） |

```jsonc
// config.json 示例（与 servers/defaults 等同级）
{
  "auth": {
    "tokens": [
      { "id": "alice",  "token": "<64位hex>", "note": "主力客户端" },
      { "id": "old",    "token": "<64位hex>", "expiresAt": "2026-10-01T00:00:00Z", "note": "到期自动失效，轮换期间新旧并存" },
      { "id": "guest",  "token": "<64位hex>", "disabled": true }
    ],
    "hmac": { "secret": "<master-secret>", "periodHours": 24, "graceBuckets": 1 },
    "hmacUsers": [   // 每人独立 HMAC secret：自动轮换 + 各自 servers 白名单（两全）
      { "id": "emp-alice", "secret": "<个人独立随机串>", "servers": ["self-limited"] }
    ],
    "rateLimit": { "windowMs": 60000, "maxFails": 10, "banMs": 600000 }
  },
  "audit": { "enabled": true, "dir": "/var/log/ssh-mcp" }
}
```

**分级授权（Token 绑定服务器白名单）**：给每个 Token 加 `servers` 数组，即可把不同"角色"限定在不同的服务器（以及不同 Linux 账户）上——配合在目标机上建低权限账户（`scripts/setup-limited-user.sh`），实现"管理员用管理员账户、普通员工用受限账户"：

```jsonc
"servers": [
  { "id": "prod-admin",   "username": "root",  "…": "…" },   // 管理员条目
  { "id": "prod-limited", "username": "aiops", "…": "…" }    // 员工条目（低权限账户）
],
"auth": { "tokens": [
  { "id": "boss", "token": "…", "servers": ["prod-admin"] },   // 管理员 → root 账户
  { "id": "emp",  "token": "…", "servers": ["prod-limited"] }  // 员工 → aiops 账户
]}
```

受限 Token：`list_servers` 只见白名单内服务器；指定白名单外的服务器一律拒绝（不泄露其存在）；未传 `server` 时默认落在全局 `defaults.serverId`（须在你的白名单内），不在白名单内则落在白名单第一个。不给 `servers` 字段 = 不限（向后兼容）。

**每人独立 HMAC（`auth.hmacUsers[]`）【备用方案】**：想要"token 每天自动轮换 + 服务器白名单"两全的角色可用，但适用于自动化脚本/无人值守程序等非交互式调用方；交互式场景（ZCode 等 IDE 内使用）推荐静态 Token + `servers` 白名单 + 秒禁用。改用每人独立 secret——`derive-token.js --secret <个人secret> --id <id>` 派生的 token 自动只开其白名单内服务器，泄露一人 secret 只影响其自身范围（吊销 = 删其 hmacUsers 条目）。注意个人 `periodHours` 非 24 时派生须传匹配的 `--period-hours`，否则桶号错位一律 401。另外要注意：全局 `auth.hmac` 派生的 Token 权限等同管理员，仅发给完全可信的调用方。

**HMAC 派生 Token（自动轮换）**：派生 Token 形如 `hmac-<bucket>-<hex>`，`bucket` 为按 `periodHours`（默认 24h）划分的时间桶号，`hex = HMAC-SHA256(secret, 桶号)`。网关接受当前桶 ±`graceBuckets`（默认 ±1）范围内的派生 Token，两端时钟按天对齐即可，无需精确同步。客户端用同一实现推导：

```bash
node scripts/derive-token.js --secret "<master-secret>"          # 当前桶
node scripts/derive-token.js --secret "<master-secret>" --at "2026-09-22T10:00:00Z"  # 验证指定时刻
```

配合 cron 每天自动更新客户端配置（示例见 `scripts/derive-token.js` 头注释）。价值：网络中流转的派生 Token 泄露后只在当前时间桶内有效；master secret 从不出现在配置头里。时钟完全不可信的内网环境可拉大 `graceBuckets`、拉长 `periodHours`，或改回静态 Token——时钟异常只会导致"拒绝"（fail-closed），绝不会导致"放行"。

- 鉴权失败一律返回统一 `401 {"code":-32001,"message":"unauthorized"}`，**不区分** Token 不存在/过期/禁用/派生越界，不向攻击者泄露信息；失败原因只记入服务端日志与审计。
- 连续鉴权失败触发防爆破封禁（见 7.2）；封禁返回 `429`。
- `/healthz` 为无鉴权探活端点，仅供 Nginx/监控检查，不暴露任何数据。
- stdio 模式由本机进程边界天然保护，无需 Token。
- 启动日志打印凭据来源数量、HMAC 参数与当前服务端时间桶（核对时钟漂移用）；弱 Token（非 64 位 hex 量级）会打警告。

### 7.2 防爆破（限速与封禁，v0.4 双维计数）

- 仅统计业务端点（`/mcp`、`/upload`、`/download`）的**鉴权失败**；成功请求永不计数；
- **双维计数**：按「来源 IP + 提交凭据指纹」二元组计数——默认 60 秒窗口内同一组合失败 ≥ 10 次，封禁该组合 10 分钟；换 Token 或换 IP 单独轮换均无法绕过；
- **整 IP 升级封禁**：同一来源 IP 跨全部凭据累计失败达 `maxFails × 3` 时，封禁整个 IP（含正确 Token 一并 429）；
- 封禁期内请求一律 `429 + Retry-After`，**不计数也不延长封禁**，到期自动解除；封禁状态在进程内存中，重启即清空；
- 阈值可通过 `auth.rateLimit: {windowMs, maxFails, banMs}` 调整；
- **来源判定（v0.4 代理白名单）**：默认取 TCP 对端地址（伪造 `X-Real-IP`/`X-Forwarded-For` 无法影响计数）；仅当对端命中 `auth.trustedProxies` 白名单时才采信代理头（取最右项）。经 Nginx 反代部署时把反代地址加入白名单（如 `"trustedProxies": ["127.0.0.1"]`）；旧开关 `SSH_MCP_TRUST_PROXY=1` 等同信任所有对端，已弃用；
- **豁免网段**：`auth.banAllowlist`（如管理网段 `"10.0.0.0/24"`）永不计数、永不 429，防管理口被连带封禁。

### 7.2b 高危命令二次确认（`auth.confirmPatterns`）

- `run_command` 命中确认清单（内置默认：rm -rf 根/引号变体、mkfs、dd 写盘、shred、`find / -delete`、重定向系统关键文件等）时**默认拒绝**，返回命中规则与指引；确认确需执行后带 `confirm: true` 重试；
- `blockedCommandPatterns` 黑名单优先级最高：命中黑名单的命令即使 `confirm: true` 也硬拒；
- 显式配置 `auth.confirmPatterns`（正则数组）时完全覆盖内置默认清单。

### 7.3 审计日志（可选，默认关闭）

在 `config.json` 中显式开启（默认**不写任何文件**）：

```jsonc
"audit": { "enabled": true, "dir": "/var/log/ssh-mcp" }   // dir 缺省为进程工作目录下的 logs/
```

- HTTP 模式每次 `/mcp` 工具调用（成功或失败）与每次鉴权失败尝试，各记一条 JSONL 到 `<dir>/audit-YYYY-MM-DD.log`（按天分文件）：

```json
{"ts":"2026-09-21T10:00:00.000Z","ip":"10.0.0.2","tokenId":"alice","tool":"run_command","args":{"command":"df -h","server":"web1"},"ok":true,"error":null,"result":{"isError":false,"text":"server: web1  exit_code: 0 --- stdout --- Filesystem ...（摘要）"}}
{"ts":"2026-09-21T10:01:12.000Z","ip":"203.0.113.9","tokenId":"invalid-1a2b3c4d","tool":null,"args":null,"ok":false,"error":"auth-failed:unknown"}
```

- 记录**命令与路径全文**便于完整复盘；工具返回附 `result` 摘要（默认头 1024 + 尾 256 字符，`audit.resultChars` 可调、`0` 关闭），复盘时能看到"当时输出了什么"；`content_base64` 与下载内容不入审计；Token 只记 `id`（失败记 8 位指纹），原值永不落盘；
- `/healthz` 与 429 封禁拒绝不产生审计记录；写失败不阻断业务（stderr 限频告警）；
- 检索直接 `grep`/`jq`；更长期的留存可叠加 Nginx access_log 与 `journalctl -u ssh-mcp`。

### 7.4 危险命令黑名单（`blockedCommandPatterns`）

正则匹配、忽略大小写，命中即拒绝执行。它用于拦截常见误操作，不是权限隔离边界；Shell 可通过变量、编码或脚本间接执行命令，因此仍须使用低权限账号与 sudo 白名单。默认内置：

| 规则 | 拦截对象 |
|---|---|
| `rm\s+-[rf]+\s+/` | 递归强删根目录 |
| `mkfs` | 格式化文件系统 |
| `dd if=/dev/zero\|random` | 覆写磁盘 |
| `dd of=/dev/sd*\|nvme\|vd` | 磁盘覆写变体（of= 侧） |
| fork 炸弹 `:(){ :|:& };:` | 自复制进程 |
| `shutdown / reboot / halt / poweroff` | 关机重启 |
| `init 0 / init 6` | 同上 |
| `> /dev/sd*` | 直写块设备 |
| `chmod -R 777 /` | 系统根目录全开放 |
| `pkill -f ""`（空模式） | 按命令行匹配**所有进程**并全杀 |
| `kill -1 / kill -9 -1 / kill -- -1` | 向全系统进程发信号（全杀） |

> 表中为便于阅读的简化写法，实际生效的完整正则以 `config.json` 的 `blockedCommandPatterns` 为准。

可按需增删正则。

### 7.5 敏感路径黑名单（`blockedPathPatterns`）

对上传/下载**双向拦截**，默认保护：`/etc/passwd`、`/etc/shadow`、`/etc/gshadow`、`/etc/sudoers`、`/etc/ssh/sshd_config`、`authorized_keys`、`known_hosts`、`/boot/`。

### 7.6 资源限制

- 命令超时默认 30s（可按次调整，上限 10 分钟），超时强制断开；
- 输出截断默认 64KB，防止 `cat` 大文件撑爆 AI 上下文；
- MCP 上传 5MB / 下载 512KB 默认上限，均可配置；
- 流式上传（/upload）默认上限 3GB（`defaults.maxStreamUploadBytes` 可调），见 6.5；
- SSH 连接默认最多并发 10 条（`defaults.maxConcurrentSsh` 可调），超出后排队等待。

### 7.7 部署安全清单

- [ ] 给 AI 使用**专用低权限 SSH 账号**，提权命令走 sudo 白名单；
- [ ] 目标服务器 22 端口防火墙只对网关机器放行；
- [ ] Token 视同服务器控制权：多客户端用 `auth.tokens` 分身份发放，轮换时新旧并存、旧 Token 设 `expiresAt` 优雅过期；泄露立即 `disabled` 或删除；
- [ ] 公网暴露务必 Nginx + HTTPS，可叠加 IP 白名单；反代场景开启 `SSH_MCP_TRUST_PROXY=1`；
- [x] 审计需求：开启 `audit.enabled` 后网关按天落 JSONL（含命令全文、调用者身份）；长期留存可叠加 Nginx access_log + `journalctl -u ssh-mcp`。

## 8. 常见问题

**Q1：启动报 `EADDRINUSE: address already in use`？**
端口被占（比如服务器上 8080 常被 Java 应用占用）。换一个端口：`SSH_MCP_PORT=18080`，Nginx 的 `proxy_pass` 同步修改。

**Q2：Node 版本要求？**
Node.js ≥ 20。Node 18（含 Ubuntu apt 版）下 MCP SDK 1.30 的 HTTP 模式会报 `crypto is not defined`。

**Q3：Windows + WSL 环境的注意事项？**
① Hyper-V 防火墙默认拦截 Windows→WSL 直连，需管理员 PowerShell 放行：
`Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow`
② WSL 空闲后网络可能漂移、重启后 IP 可能变化，重跑测试直接用 `bash scripts/start-wsl-test.sh`（自动重启 WSL、更新 config.json 里的 IP 并连跑全部测试）。生产环境（真实 Linux 服务器）无此问题。

**Q4：AI 执行命令报"命令被安全策略拦截"？**
命中了黑名单正则。若确属误拦，在 `config.json` 的 `blockedCommandPatterns` / `blockedPathPatterns` 中调整后重启网关。

**Q5：交互式命令怎么办？**
网关按设计只支持非交互命令。vim → `sed -i` / heredoc 整体写回；top → `top -bn1 | head -20`；tail -f → `tail -n 200`；改 JSON 配置 → `python3 -c`。AI 通常会自行选择替代写法。

**Q6：怎么批量把新服务器接入管理？**
编辑 `config.json` 的 `servers` 数组追加条目即可，无需重启进程（stdio 每次拉起时读取；HTTP 模式重启 systemd 生效：`systemctl restart ssh-mcp`）。
