# 目标

后台任务目录改为**按 SSH 账户隔离**的多用户布局（`/tmp/.ssh-mcp-jobs/<账户名>/<job_id>/`），使同一网关上多个不同权限的服务器账户（root 管理员条目 + aiops 受限条目）能并存使用后台任务——这是分级授权落地到真实多账户部署的前置修复。

# 范围

- lib.js 三个任务函数（startBackgroundJob/checkJob/killJob）：任务目录从 `/tmp/.ssh-mcp-jobs/<id>` 改为 `/tmp/.ssh-mcp-jobs/<serverCfg.username>/<id>`；
- 根目录 `/tmp/.ssh-mcp-jobs` 防护：拒符号链接；`install -d -m 0711`（其他用户可穿越+创建、不可列举，防探测）；不再对根目录做属主校验（多用户语义下属主为首个创建者，合法）；
- 账户子目录 `install -d -m 700` 且属主校验（该 SSH 账户本人）——原"防止误删/接管"防护语义保留在账户级；
- checkJob 的 7 天清理限定在**本账户**子目录内（跨账户不可见也不越权清理）。

# 非目标

- 不改 ACL/鉴权/审计；不改变任务文件格式（out.log/pid/code/killed）。

# 验收示例

- A1：既有后台任务全生命周期测试在新布局下全绿（原有测试天然覆盖：测试目标账户为 root，目录为 /tmp/.ssh-mcp-jobs/root/<id>）。
- A2：root 与第二个账户（测试目标机同机不同账户）各自启动后台任务互不可见、互不干扰。

# 决策

- D1（用户 2026-09-24 要求在 1.6 上为新同事开通低权限角色，原 root 条目不动）：多账户并存要求任务目录按账户隔离。依据既有授权免确认推进。
- D2：根目录 0711（穿越+创建、防列举）；账户目录 700 属主校验——多用户下最简且安全的布局。
