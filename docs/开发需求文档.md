## 1. 背景与目标

### 1.1 背景

在"用 AI 运维服务器"的场景下，存在三个现实问题：

1. **AI 不能直接拿 SSH**：让 AI 直连服务器 22 端口，意味着密钥/密码暴露给 AI 侧、且执行行为不可控，`rm -rf` 一类操作没有闸门；
2. **云服务器端口收敛**：生产/测试云主机的安全组通常只放行少量端口，为 AI 单独开 SSH 通道不现实；
3. **传统运维平台不匹配**：以 Jpom 为例，其开放 API 是"触发器"模式——只能触发预定义脚本、异步查日志，无法满足 AI"现场发一条命令、同步拿结果"的交互需求。

### 1.2 目标

做一个轻量 **MCP 网关**：AI 只访问网关暴露的受控工具接口，网关在服务器内网侧持有 SSH 密钥发起连接，实现——

- AI 发命令、传文件，同步拿结果；
- 危险操作在网关侧被拦截，AI 无法绕过；
- 对外只暴露一个 HTTP 端点（可套 Nginx/HTTPS），目标服务器 22 端口不额外开放。

## 2. 用户故事

| # | 角色 | 故事 | 价值 |
|---|---|---|---|
| US1 | 运维人员 | 我把服务器信息写进 config.json，让 AI 能帮我查看磁盘、重启服务、部署文件，而不用把 SSH 密钥交给 AI | 统一管控出口 |
| US2 | AI 使用者 | 我对 AI 说"看下 web1 的内存"，AI 执行 `free -h` 并直接把结果讲给我 | 自然语言运维 |
| US3 | 安全管理员 | 我配置危险命令黑名单和敏感路径黑名单，AI 说破天也执行不了 `rm -rf /`，也读不到 `/etc/shadow` | 事故闸门 |
| US4 | 平台负责人 | 我的云服务器安全组只开 443，AI 通过 Nginx 反代的唯一入口访问网关 | 端口零新增 |

## 3. 功能需求

### FR1 远程命令执行

**描述**：AI 通过 `run_command` 工具在指定服务器执行单条非交互 shell 命令，同步返回结果；支持后台执行与工作目录指定（详见 FR9）。

**验收标准**：
- 返回 `server`、`exit_code`、`stdout`、`stderr`；非零退出码与 stderr 内容如实透传；
- 命令默认超时 30000ms，可用 `timeout_ms` 调整（上限 600000ms），超时强制断开连接并明确标注；
- stdout/stderr 各自超过 `maxOutputBytes`（默认 65536 字节）时智能截断：保留头部 60% + 尾部 40%，标注 `truncated` 与省略字节数（命令开头回显与结尾报错同时可见）；
- 可选 `cwd` 参数：执行前先切换到指定目录，目录不存在返回 shell 错误（exit_code 1）；
- 连接类网络错误（ECONNREFUSED / EHOSTUNREACH / ETIMEDOUT / ECONNRESET / EPIPE）自动重试一次（间隔 1.2s）；
- 每次调用建立独立连接，无状态、互不干扰。

### FR2 文件上传

**描述**：AI 通过 `upload_file` 工具（SFTP 通道）将 base64 内容写入服务器指定路径。

**验收标准**：
- 参数：`remote_path`（必填）、`content_base64`（必填）、`mode`（可选八进制权限，如 0644）、`server`（可选）；
- 父目录不存在时自动创建（`mkdir -p` 语义）；
- 上传完成后返回服务端实测 md5，与本地内容 md5 可比对校验完整性；
- 单文件上限 `maxUploadBytes`（默认 5242880 字节 = 5MB），超限报错并提示改用命令行工具传输；
- 支持八进制权限设置，`chmod` 失败时报错。

### FR3 文件下载

**描述**：AI 通过 `download_file` 工具读取服务器上的文件。

**验收标准**：
- 参数：`remote_path`（必填）、`max_bytes`（可选，默认 `maxDownloadBytes` = 524288 字节）、`server`（可选）；
- 目标为目录时报错；文本文件以 `utf8` 返回、二进制以 `base64` 返回（`encoding` 字段标注）；
- 返回 `size` 与 md5，供 AI 侧还原后比对；
- 超过大小上限时明确报错，并提示可用 run_command（head/tail/split）分段读取或调大 max_bytes。

### FR4 多服务器管理与分级授权

**描述**：网关支持在 config.json 中声明式配置多台服务器，AI 按服务器 ID 选择目标；每个 Token 可绑定 `servers` 白名单，实现"不同角色访问不同服务器/账户"的分级授权。

**验收标准**：
- 每台服务器含 `id`、`name`、`host`、`port`、`username`、`privateKeyPath` 字段，私钥路径支持 `~` 展开；
- `list_servers` 列出全部服务器并标注默认服务器；
- `run_command` / `upload_file` / `download_file` 均支持可选 `server` 参数；缺省时使用 `defaults.serverId`；
- 引用不存在的服务器 ID 时报错并列出可用 ID；
- `auth.tokens[].servers`（可选）：绑定后该 Token 的 `list_servers` 仅见白名单内服务器，工具与 `/upload`、`/download` 端点均只能访问白名单内服务器，未传 `server` 时默认取全局 `defaults.serverId`（须在白名单内），不在白名单内则取白名单第一个；越权请求拒绝且不泄露白名单外服务器的存在；引用未定义的服务器 id 时拒绝启动；未配置 `servers` 字段的 Token 行为完全不变（向后兼容）。

### FR5 安全拦截与鉴权

**描述**：网关在执行前对命令与路径做双向安全检查；HTTP 模式提供多来源 Bearer 鉴权（多 Token 身份管理、HMAC 派生 Token 自动轮换【备用方案，交互式场景推荐静态 Token】）、防爆破（限速与封禁）与可选审计日志。

**验收标准**：
- `blockedCommandPatterns`（正则、忽略大小写）命中即拒绝，返回命中规则说明；默认覆盖 `rm -rf /`、mkfs、磁盘覆写 dd（if= 与 of= 两侧）、fork 炸弹、关机重启类、直写块设备、`chmod -R 777 /`、全杀命令（`pkill -f ""` 空模式、`kill -1`/`kill -9 -1`/`kill -- -1`）；
- `blockedPathPatterns` 对上传/下载双向拦截，默认保护 passwd/shadow/gshadow/sudoers/sshd_config/authorized_keys/known_hosts//boot；
- HTTP 模式三类凭据来源（`SSH_MCP_TOKEN` / `auth.tokens` / `auth.hmac`）全缺时拒绝启动；`auth.tokens[]` 支持 `id`（身份标识）、`expiresAt`（到期自动失效）、`disabled`（禁用）、`servers`（服务器访问白名单），仅配置环境变量 Token 的旧部署行为完全不变；
- `auth.hmac` 派生 Token（`hmac-<桶号>-<HMAC-SHA256 hex>`）默认按 24h 分桶、接受当前 ±1 桶，桶号/hex 篡改或越界一律拒绝；校验只用网关本地时钟（fail-closed，时钟异常仅导致拒绝、不会放行）；`scripts/derive-token.js` 与网关共用同一实现；
- `auth.hmacUsers[]` 每人独立 HMAC：各自 secret + 各自 `servers` 白名单 + 各自周期，token 格式 `hmacu-<id>-<桶>-<hex>`；泄露一人 secret 仅影响其自身白名单范围，吊销 = 删条目；与全局 `auth.hmac` 并存；
- 鉴权失败（不存在/过期/禁用/派生越界）对外统一 `401 unauthorized`，不泄露失败原因；原因仅记入服务端日志与审计；
- 同一「来源 IP + 提交凭据指纹」组合在窗口内鉴权失败达到 `auth.rateLimit.maxFails`（默认 10 次/60s）后封禁该组合 `banMs`（默认 10 分钟）；同一来源 IP 跨凭据累计失败达 `maxFails×3` 升级封禁整个 IP——两种封禁期内所有请求返回 `429 + Retry-After`，不计数不延长，到期自动解除；来源判定默认取 TCP 对端，仅当对端命中 `auth.trustedProxies`（IP/CIDR 白名单）时采信 `X-Real-IP`/`X-Forwarded-For` 最右项（旧开关 `SSH_MCP_TRUST_PROXY=1` 等同信任所有对端，已弃用）；`auth.banAllowlist` 豁免网段永不计数封禁；
- 高危命令二次确认：`run_command` 命中 `auth.confirmPatterns`（内置默认清单，可整体覆盖）时默认拒绝并返回命中说明，`confirm: true` 复核后执行；黑名单优先于确认清单（命中黑名单即使 confirm 也硬拒）；内置最低限度黑名单与 config 黑名单合并生效（根分区覆写的引号/包裹变体不依赖部署方 config 更新）；
- 内置可选 TLS：`SSH_MCP_TLS_CERT`/`SSH_MCP_TLS_KEY`（或 config `tls` 段）成对配置后以 HTTPS 监听全端点，未配置保持 HTTP；配套 `scripts/gen-cert.sh` 自签证书生成；Token 可改由 `SSH_MCP_TOKEN_FILE`（0600 类私有权限文件）提供，与 `SSH_MCP_TOKEN` 互斥；
- `audit.enabled=true`（默认关闭）后，HTTP 模式每次工具调用与鉴权失败按天写 JSONL 审计（时间、来源 IP、Token 身份、工具名、命令/路径全文、结果、返回结果摘要 `result`——头 `audit.resultChars` 默认 1024 + 尾 256 字符，可调可关），不记录 `content_base64` 与下载内容，Token 原值永不落盘；关闭时零磁盘副作用；
- `/healthz` 探活端点无鉴权且不暴露数据；
- 服务器配置支持 `hostFingerprint`（SHA-256 格式，SSH 中间人防护）与 `allowedFileRoots`（文件操作目录白名单，防 `..` 逃逸与越权写入）；
- 拦截动作发生在网关侧，用于降低常见误操作风险；命令黑名单不作为权限隔离边界，真正的权限限制由低权限 SSH 账号与 sudo 白名单承担。

### FR6 双传输模式

**描述**：同一份代码支持 stdio（本机 AI 客户端拉起）与 HTTP（部署服务器、供远程 AI 调用）两种 MCP 传输。

**验收标准**：
- `SSH_MCP_TRANSPORT=stdio`（默认）时以 stdio transport 运行，日志全部走 stderr；
- `SSH_MCP_TRANSPORT=http` 时监听 `SSH_MCP_HOST:SSH_MCP_PORT`（默认 127.0.0.1:8080），提供 `/mcp` 端点与 `/healthz` 探活；
- HTTP 模式采用无状态设计（每请求独立 server+transport），不依赖会话粘性，Nginx 可任意反代/负载均衡；
- 经 Nginx 反代后六个工具全流程可用（可用 `node test-nginx.js` 验证）。

### FR7 单文件打包部署

**描述**：通过 SEA（Single Executable Application）打包自带 Node 运行时的单个可执行文件，目标服务器零安装。

**验收标准**：
- `bash scripts/build-linux.sh` 一键产出 `dist/ssh-mcp-server-linux`（约 120MB，Linux x64）；
- 产物在无 Node、无 npm、离线的服务器上直接运行（`SSH_MCP_TRANSPORT=http ... ./ssh-mcp-server-linux`）；
- 配置文件查找顺序：`SSH_MCP_CONFIG` 环境变量 → 可执行文件同目录 → 当前工作目录；
- 单文件可注册为 systemd 服务并开机自启、崩溃自动拉起（Restart=always）。

### FR8 大文件流式上传/下载

**描述**：HTTP 网关提供 `POST/PUT /upload` 与 `GET /download` 流式端点，绕开 MCP JSON/base64 通道的体积天花板（GB 级文件的 base64 会超出字符串上限），请求/响应体直接在网关与目标机 SFTP 之间流式搬运。

**验收标准**：
- 上传：查询参数 `path`（必填，绝对路径）、`server`、`mode`（可选八进制权限）；父目录自动创建、覆盖写；成功返回 `200 {"ok":true,"remotePath","bytes","md5"}`，md5 为远端 `md5sum` 实测值；
- 上限 `defaults.maxStreamUploadBytes`（默认 3GiB）双重校验：`Content-Length` 超限即刻 413（不建立 SSH 连接）；流式计数超限返回 413 且删除远端半截文件；客户端中断同样清理残片；
- 下载：查询参数 `path`（必填）、`server`；响应头 `X-Md5`/`X-File-Size` 先行返回，SFTP 读流直透响应体，不限大小，不做断点续传；
- 服务端流式管道、恒定内存（不缓存全量、不落网关磁盘）；`server.requestTimeout=0` 传输不受 300s 默认请求超时限制；
- Bearer 鉴权、防爆破（401 计数）、审计（`upload_stream`/`download_stream` 条目，不记文件内容）与 /mcp 同一套；敏感路径黑名单对两个端点同样拦截；
- 零新增依赖；配套修复 `express.json` 请求体上限与 `maxUploadBytes` 挂钩（修复 HTTP 模式 base64 上传被默认 100KB 限制挡住的问题）。

### FR9 后台任务

**描述**：`run_command` 支持 `background: true` 在目标机 nohup 后台执行长任务（编译、批处理等），立即返回 `job_id`；配套 `check_job`/`kill_job` 工具管理任务生命周期；`cwd` 参数支持指定工作目录。

**验收标准**：
- 后台启动立即返回 `job_id`（12 位随机 hex），命令仍先过黑名单；`cwd` 参数前台/后台均生效；
- 任务状态文件在目标机 `/tmp/.ssh-mcp-jobs/<job_id>/`（out.log/pid/code），**网关重启后 check_job 仍可查询**；目标机 /tmp 重启即自然清理，check_job 顺带删除 7 天前旧目录；
- `check_job` 返回 state（running/done/killed）、exit_code（结束时）与输出尾部（`tail_lines` 默认 50，上限 500）；
- `kill_job` 终止运行中任务（TERM → 0.5s KILL，含直接子进程），state 变为 killed；
- 新增工具零依赖，不改变现有四工具既有行为。

## 4. 非功能需求

### NFR1 性能

- 命令执行默认超时 30s，可按调用调整至最高 10 分钟；连接建立预留 15s，SSH keepalive 10s；
- 输出/上传/下载均有字节上限，防止单次调用耗尽 AI 上下文或网关内存；流式上传（FR8）恒定内存且不受请求级超时约束；
- 连接失败自动重试一次，抖动场景对 AI 透明。

### NFR2 安全

- 鉴权、命令黑名单、路径黑名单三道闸门（见 FR5）；鉴权层附加防爆破限速与统一 401（不泄露凭据状态）；
- 私钥仅存于网关侧文件系统，永不出现在 AI 可见接口与日志中；Token 原值与 HMAC secret 永不落入日志/审计/响应；
- 鉴权与防护零新增依赖（限速/封禁/派生均为 Node 内置 crypto 与内存实现），不增加单文件打包体积；
- 部署清单要求：AI 使用专用低权限 SSH 账号、目标机 22 端口仅对网关放行、Token 定期轮换（`expiresAt`/派生 Token 均可自动化）。

### NFR3 可维护性

- 核心逻辑（`lib.js`：配置/SSH/SFTP/拦截）与 MCP 协议层（`server.js`）解耦，可脱离协议直接测试；
- 全部行为由 `config.json` + 环境变量驱动，不改代码即可调整安全策略与服务器清单；
- 测试脚本覆盖各层并可重复执行：`test-direct.js`（直连）、`test-mcp.js`（stdio）、`test-http.js`（HTTP+401）、`test-nginx.js`（反代全链路）。

## 5. 约束与技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 20 | MCP SDK 1.30 的 HTTP 模式依赖（node18 会报 crypto is not defined） |
| MCP 协议 | @modelcontextprotocol/sdk | 官方 SDK，stdio + StreamableHTTP 双 transport |
| SSH/SFTP | ssh2 | 纯 JS 实现，密钥认证，同时覆盖 exec 与 sftp 通道 |
| HTTP 服务 | express | 轻量路由 + 中间件（鉴权/探活） |
| 单文件打包 | Node SEA + esbuild + postject | 官方方案；bundle 全依赖内联，产物离线可用 |
| 认证方式 | SSH 密钥（password 仅用于一次性装钥，见 bootstrap-host.js） | 免密、可审计、可轮换 |

## 6. 非目标

- ❌ 不支持交互式终端会话（vim/top/tail -f），文档提供替代写法；
- ❌ 不提供 Web 管理界面；
- ❌ 审计仅内置 JSONL 文件落盘（`audit.enabled` 显式开启，见 FR5），不做审计落库、检索界面与告警；
- ❌ 不做多租户、多用户权限体系（多 Token 仅区分身份用于审计，不做工具级授权差异）；
- ❌ 不做 SSH 密码认证的常态支持（仅引导脚本一次性使用）。

## 7. 后续规划（⚠ 非本期范围）

以下为路线图条目，**本期均未实现**，仅作为演进方向记录：

1. **审计日志检索与落库**：本期已内置 JSONL 文件审计（见 FR5）；此处指数据库化存储、查询界面与告警通知；
2. **审批流**：多 Token 身份已实现（见 FR5）；此处指高危命令二次审批与最小授权策略；
3. **交互式命令会话**：受限的伪终端（PTY）支持；
4. **文件增量同步**：目录级 rsync 语义的批量传输；
5. **流式上传断点续传**：流式端点已支持 3GB 级直传（见 FR8）；此处指分块、断点续传与并行加速；
6. **Web 管理面板**：服务器管理、执行历史可视化的配套前端；
7. **HMAC 自动轮换（备用方案）**：`auth.hmac` / `auth.hmacUsers` 已开发并合入（见 FR5），适用于自动化脚本、无人值守程序等无法手动更换 token 的调用方；交互式场景（ZCode 等 IDE 内使用）推荐静态 Token + `servers` 白名单 + 秒禁用。
